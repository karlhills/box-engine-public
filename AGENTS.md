# AGENTS.md

Guide for AI coding agents (and humans) working in this repository. Keep it short, current and true. If you change a command, a convention or the layout, update this file in the same change.

## What this is

box-engine: a Rust 3D game engine with an integrated editor, focused on stylized worlds and procedural creation. Latest milestone: **M8, second game validation**, done except the Windows run; M9 (external developer readiness) is next ([docs/ROADMAP.md](docs/ROADMAP.md)); M7 is done except the Windows run; M6 is done except the Windows run; M3–M5 are done except the Windows runs; M2 is done except the Windows run; M1 is done except the Windows run and a Tracy capture ([IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)). Planning documents are in [docs/](docs/); decisions are in [docs/DECISIONS.md](docs/DECISIONS.md).

Dependency direction: `box_editor`/`box_cli → box_engine → box_render → box_core`, `box_editor → box_assets → box_core`, `box_engine → box_proc → box_core`, `box_physics → box_core` (`box_engine` re-exports it behind the default `physics` and `dynamics` features; `box_editor` uses it for picking), and `box_engine → box_audio → box_assets/box_core` (re-exported behind the default `audio` feature), and `plugins/box_arch → box_proc → box_core` (box_arch also depends on box_core directly and dev-depends on box_engine/box_editor for examples and tests; no engine crate depends on box_arch)., `box_engine → box_ui → box_render/box_assets/box_core` (box_ui uses only box_render's `Overlay` and `Camera` types), and `box_engine → box_script → box_core/box_assets/box_physics` (default `script` feature)., and `box_editor`/`box_cli → box_export → box_engine`. Never the reverse. winit types stay in `box_engine` and `box_editor`; wgpu types stay in `box_render` and `box_editor`. Engine crates that `#[derive(Reflect)]` also need `bevy_reflect.workspace = true` (the derive emits `bevy_reflect::` paths); game crates get the name from `use box_engine::prelude::*` and need no `bevy_reflect` dependency.

Runner flags (any example): `--capture <png>` headless render of the last frame (with `{frame}` in the path, every frame as a numbered sequence), `--frames <n>`, `--headless` (no window and no capture: run `--frames` frames offscreen), `--size <W>x<H>`, `--report <json>` frame timings, render statistics (draws, shadow draws and casters, triangles, uploads) and the slowest frames by index; it also records `render_submit_ms`, the GPU frame time `gpu_ms` and pass intervals `gpu_pass_ms` (timestamp queries; headless runs), and each summary has a `min`. Headless runs use a fixed 1/60 s step and wait for the GPU each frame, so captures are deterministic and timings include GPU work. A capture run exits non-zero if wgpu reported validation errors. Player binaries reject unknown flags; examples keep passthrough flags. `--control` serves the live control socket (`box mcp` live tools) for the app's project (the `Scenes` resource's project root, which the player sets; an error without one). With `--control`, headless runs are paced to 60 fps and `--headless --control` without `--frames` runs until the `stop` method ends it.

## Definition of done

1. `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass.
2. **Visual changes have a capture.** Render with `--capture`, open the PNG and look at it. Code reading alone is not verification. Mention the capture path in your summary.
3. Golden images still match, or were re-recorded deliberately and the new PNGs reviewed.
4. No wgpu validation errors (`FrameStats::validation_errors == 0`).
5. No unused scaffolding, stubs or unwired options.
6. Docs updated when behaviour, commands or decisions change.

## Conventions

- Right-handed, **+Y up, −Z forward**, metres, radians. Colours are linear (`Color::srgb`/`Color::hex` convert from sRGB).
- Reverse-Z depth in the main pass; standard depth in shadow maps.
- Library crates return `Result` with `thiserror` errors; examples and binaries use `anyhow`. No panics on bad input or bad assets. `unsafe` is denied workspace-wide.
- Logging through `tracing`; profiling scopes through `profiling` (`--features box_engine/tracy` for Tracy).
- Systems are `fn(&mut World)`, added with `app.add_system(Stage::Update, f)`. Transform propagation runs at the start of `PostUpdate` and is change-driven (each entity's `Transform`/`Parent` is compared with a cached copy), so mutate transforms freely. Never write `GlobalTransform`; use `transform::compute_global` between propagations.
- **hecs 0.11 query iterators yield only the query item.** Ask for `Entity` explicitly: `world.query::<(Entity, &Transform)>()`.
- Expensive work (mesh rebuilds, buffer reallocation, shader compilation) never runs unconditionally per frame. It is change-driven or throttled.
- **Scene data is reflected.** A saved component: `#[derive(Reflect, Default, Clone)]` and `#[reflect(Component, Default, Clone)]`, then `registry.register_all::<(A, B)>()` (or `register::<T>()`) in `Plugin::register`. Engine crates also add `#[type_path = "box_engine"]`; game types do not need it (the registry and scene files use the short name). Field metadata: `#[reflect(@Range { min: 0.0, max: 1.0 }, @Unit("m"))]`; `Range`, `Unit`, `Step`, `Hidden`, `NotSaved`, `Logarithmic` and `bevy_reflect` come with `box_engine::prelude::*`. The doc comment is the tooltip. Resources use `#[reflect(Resource)]` and `register_resource`. Registration errors are kept and logged by `Game` with the plugin name. Get the full registry from `box_engine::engine_registry()`. Unregistered components are runtime-only and never saved; scene loads warn about unknown component types with a did-you-mean.
- **All scene edits go through `box_core::edit`** (`EditStack` or JSON `Command`s), never raw `World` mutation, so the editor, the CLI and later MCP share validation and undo. Entities are addressed by `Uid`.
- Post-processing settings are `Environment.ambient_occlusion/bloom/color_grading`; new `Environment` fields need `#[reflect(Default)]` defaults so old scenes load.
- Imported level geometry collides through `ColliderShape::Mesh` (the entity's MeshAsset triangles, static only); set `"colliders": true` in a glTF's .meta to give every mesh node one.
- **Crash reports:** apps call `box_engine::crash::install(kind)` once on the main thread (`player::run_game`, `Game::run`, the editor and `box` already do). Engine code that catches panics uses `box_core::panic_guard::catch`, never bare `catch_unwind`, so caught panics are not reported as crashes. Reports go to `~/Library/Logs/box-engine` / `%LOCALAPPDATA%\box-engine\logs` (`BOX_CRASH_DIR` overrides); nothing is uploaded. Error messages say what happened, where, and what to do (see docs/TROUBLESHOOTING.md); file errors use `box_engine::io_hint::text`.
- Game visibility is `Visible(bool)` (saved, inherited; meshes, local lights, particles, picking), distinct from the editor-only `box_render::Hidden`. Runtime-only entities carry `Transient` (never saved, despawned on save load). Script API renames go through `box_script::deprecated_alias`; stability rules are in docs/STABILITY.md, contribution rules in CONTRIBUTING.md.
- Read project files through `box_assets::vfs` (`read`, `is_file`, `is_dir`, `read_dir`), never `std::fs`, so exported games (a mounted pak) work. A native player bin uses `options.default_project(dir)`.
- Changing a saved type: a new field with a default needs nothing. A rename, move, removal or meaning change needs `registry.add_migration("Type", MigrationStep::new(..)…)` in `Plugin::register` (append-only, each with a fixture); type renames use `registry.rename_type`. See docs/FORMATS.md.
- **Optional engine modules** are box_engine features `physics`, `dynamics`, `audio`, `script` (all default; `dynamics` and `script` need `physics`). Gate every use with `#[cfg(feature = "…")]` and give a test file that needs one `required-features` in `crates/box_engine/Cargo.toml`. A new saved type of a module goes into `box_engine::modules::MODULES` (a test checks the lists against the registration functions), so scenes that use it in a build without the module warn with the feature name. Generated native projects pass the modules through as their own features (`default = [...]`); the editor always has every module. In `cargo … --workspace`, features are unified: check a feature set with `-p`.
- **Look:** atmosphere, sky, grading, vignette and wind are `Environment` fields, uniforms only; animate them freely (time of day). Swaying materials set `StandardMaterial.wind`, or call `wind_offset` in a material shader's `vertex` hook (every pass runs it). A transparent material with `depth_fade > 0` runs the depth prepass while visible.
- A change-driven system that keeps derived state in step with saved data (anchors) can also run in an editor's edit world: `app.add_edit_world_system(stage, label, fn)` (box_core `EditWorldSystems`; `Game::edit_world_systems`). Gameplay systems never run there. A game with its own event loop (an egui UI over the scene) feeds `Input` with `box_engine::apply_window_event`, as the runner does.
- **Local lights:** point and spot lights share one counted buffer (256); only one local light per frame is shadowed (the most important with `shadows`). Interiors get an `AmbientVolume` (sky_contribution 0) so the sky ambient does not leak in. Particles are `ParticleEmitter` components simulated by `simulate_particles` (PostUpdate, after propagation; runtime `ParticleState`, never saved); one-shot effects use `ParticleEmitter::burst(n)` with `despawn_when_finished`.
- **Animation:** put `AnimationPlayer` (and optionally `AnimationStateMachine`) on the entity whose descendants are the joints, usually a `PrefabInstance` of a glTF. Clips bind by joint `Name`. Steer machines with `set_float`/`set_bool`/`trigger`; read `AnimationStateMachineState::current()` and `AnimationPlayerState::finished()`. Joints are ordinary instanced entities: attach things to them, never write `GlobalTransform`. Never build `SkinnedMesh` by hand for glTF models; the glue makes it from `SkinBinding`.
- **Dynamics** (`dynamics` feature): add `RigidBody` next to a non-trigger `Collider` on the same entity; set `Velocity` for initial or runtime velocity; move kinematic bodies with `Transform` or `Velocity`; writing `Transform` teleports. Forces and impulses go through `Physics::apply_impulse` and friends and apply at the next step. `step_dynamics` is the first FixedUpdate system (`physics_step`); read `CollisionEvent`s after it. One `Joint` per entity; its rest pose is the pose when first simulated. Simulation state lives only in the `Dynamics` resource, never in saved components.
- **Game UI** is retained (`box_ui`): add nodes once, update with setters, read `Events<UiEvent>` (`is_click`); never rebuild per frame; no egui in game code for new UI. A `modal` root owns focus and captures actions; put a pause action in `ui.settings.passthrough_actions`. Theme: `ui.set_theme(path)`. Labels: `at_entity("Name or uid", offset)`. String tables live in `assets/strings/<lang>.strings.json`; switch with `Strings::set_language`.
- **Save games:** entities with a `Uid` are saved (`Saveable` for runtime spawns, `SaveExclude` to skip); other state goes through `SaveHooks::add`; request with `SaveGames::save`/`load`; bump `SaveConfig::version` and provide `migrate` when saved data changes meaning. Data tables: call `data_table(world, path)` each time, or compare `data_version`.
- **Scripts** are `.luau` files under `assets/`, attached with the `Script` component; they run only in playing worlds (`Game::app` adds `ScriptPlugin` after the game's plugins). Values crossing into Luau are copies; writes patch. Bind a crate's runtime API to Luau with a `box_script::ScriptApi` added in `Plugin::build` (`app.add_script_api`); registered components, resources and events (`registry.register_event::<T>()`, `#[derive(Reflect, Clone)]` + `#[reflect(Default)]`) need no binding. Script errors log under the `box_script` target with `file:line`.
- **Script rules:** a `.luau` file defining `rule(intents, out)` is a rule for every `ScriptIntent` that names it; it runs in the edit world and in Play through `box_script::ScriptRules` (a `RuleSource`), never touches the world, and is named by its assets-relative path (use that name in `Overrides` and `set_enabled`). Rules found at run time use `app.add_rule_source`. A rule file may declare `scope = "intent"` or `{ neighbours = r }` (its parts depend only on the intent, or on intents within r metres); then an edit runs it only for the affected intents. Never use `math.random` or cross-intent counts in a scoped rule; derive variation from the intent.
- Script bindings of a crate's runtime API live in that crate's plugin (box_ui `ui`/`strings`, box_engine `script_glue`), or in box_script when the crate is below it (physics, characters). Turn Rust events into script handlers with `ScriptSignals` + `box_script::subscribe`; add entity methods with `entity_methods` and declare them in `ScriptApi::entity_definitions`. Every box_engine app has `CharacterPlugin` (`ScriptPlugin` adds it too); `scripts_fixed_update` runs after `physics_step` and native systems ordered before `move_characters`, and before `move_characters`, so `on_fixed_update` input moves characters in the same step (it sees the previous step's character state; read the result in `on_update`). `on_load` runs after `on_start`'s first part: set defaults in `on_start`, restore in `on_load`. Scripts that build UI remove it in `on_destroy` (loading a save replaces their entity).
- Editor overlays (grid, gizmos, selection) use the post-tonemap `LineLayer::Display*` layers so their colours do not depend on exposure.
- **Games are plugins.** `impl Plugin`: `register` adds saved types to the registry, `build` adds resources, events and systems. `box_engine::Game::new().with_plugin(p)` holds the plugins and the registry; the editor (`box_editor::run_game(options, game)`), the player (`player::run_game(options, game)`), Play sessions and tests (`game.new_app()`, then `app.run_frames(n, dt)`) start from it. `app.add_plugin(&p)` on an app whose registry lacks the plugin's types warns. `app_with_world` adds `InputPlugin`, `ScenePlugin`, `AssetGluePlugin` and `PhysicsPlugin` first; games do not add them again. `FixedUpdate` runs at `FixedTime::step` (60 Hz, at most 5 catch-up steps) before `Update`; inside it `Time::delta` is the step. Events: `app.add_event::<T>()`, send with `Events<T>::send`, read once with an `EventCursor<T>` kept in the system's closure; queues advance only on frames where a fixed step ran, so FixedUpdate readers see every event at any display rate. Helpers: `world.find_by_name`, `first_with::<T>()`, `count::<Q>()`, `component_mut`, `resources_mut::<(A, B)>()`; `Primitive::cuboid/sphere/…`, `StandardMaterial::color`; `Physics::ray`; `CursorOptions::lock/release`. Logging in games: `info!`/`warn!`/`error!` from the prelude.
- **Games read input through named actions.** Define an `ActionMap` resource (builder or JSON) and read `Actions` (`pressed`/`held`/`released`/`axis1`/`axis2`; `axis2` +Y is forward). `pressed`/`released` fire once per frame in Update and once per fixed step in FixedUpdate (a press in a frame without a fixed step reaches the next step). Unknown action names read as zero and are logged once. Cursor lock: set the `CursorOptions` resource (`CursorOptions::locked()`/`free()`) and read mouse look from `Input::mouse_delta`; `active_grab` says what is actually applied. To feed input from outside the runner (editor Play mode) use the `Input` setters, a `box_engine::GamepadPoller`, and call `Input::end_frame` after each frame.
- Editor-only game extensions (viewport tools, palette actions) are an `EditorPlugin` passed to `box_editor::run_game_with`; path intents get a tool from `path_tool::PathToolConfig`. A rule reading another intent type declares it with `app.rule_reads::<T>(name)`. Per-part manual changes are `Overrides` on the owner, applied by `reconcile`; never edit derived parts directly. Tool previews are `derived::Preview` owners (generated: never saved).
- Scatter instances are runtime entities under derived chunk parts; never spawn or edit them; edit the `Scatter` (its `mask` through the Paint Scatter tool). Headless captures get them through `settle_assets`.
- **A generator is a reflected component**: `#[derive(Reflect, Clone, PartialEq)]`, `#[reflect(Component, Default, Clone)]`, a `Default`, then `impl Generator` (`VERSION`, `generate`, optional `MATERIAL_SLOTS`, `CATEGORY`, `inputs`). Register it with `registry.register_generator::<T>()` in `Plugin::register`; it then regenerates everywhere and appears under Add ▸ <category>. Bump `VERSION` whenever output changes for the same parameters (golden fixtures enforce it). Generators are pure: randomness only from `ctx.rng()`, never world access. Their output is bit-identical on every platform (D17): use `box_core::pmath::{sin, cos, atan2, powf, ...}`, never `f32::sin` and friends (the platform C library differs in the last bit); `clippy.toml` in box_core, box_proc and box_arch enforces it, and glam is built with `libm` so its rotations are portable too. Runtime state belongs in `ProcState`, never in the generator or `Procedural`.
- Runtime-only generated entities (`Instanced`, `Derived`) are tested with `prefab::is_generated` / `NotGenerated<Q>`, never one marker alone. Part keys are semantic: `PartKey::new(owner_uid, "role")`. A part component is compared with `PartialEq` on every reconcile: do not put runtime caches in part components.
- React to components and events with hooks, not lazy-init passes: `app.on_add::<T>(|world, e| …)` runs once per entity that gets `T` (spawn, insert, scene load); `app.on_remove::<T>` runs after removal or despawn; `app.on_event(stage, |world, &e| …)` owns the cursor. Send events with `world.send(e)`.
- Structural changes while iterating go through `world.defer()` (spawn, insert, remove, despawn, set_parent); the app applies them after every system. No collect-then-apply loops.
- Order systems by name with `app.system(stage, f).after("name")/.before("name")/.label("x")`; `app.check_order()` in tests. Plain `add_system` keeps insertion order.
- Entities moved in FixedUpdate get `Interpolated`; read `interpolated_transform` to follow them. New games set `RuntimeEntities::DespawnUnlessPersistent` on `Scenes` and mark carry-over roots `Persistent`. Character movement is `KinematicCharacter` plus `CharacterPlugin` (or `Physics::move_and_slide`); timed behaviour uses `Timer` and `Tween`, ticked by `Time::delta`, so time scale and pause apply.
- Tunables shared across scenes are settings resources (`registry.register_settings::<T>()`, file `assets/settings/<Type>.json`, hot-reloaded); input bindings can be overridden by `assets/settings/input.actions.json`.
- **Physics** queries see colliders as of the last `sync_physics` (the previous frame's PostUpdate). Exclude the querying entity with `QueryFilter::excluding`. Trigger events are sent in PostUpdate; read them next frame.
- `MeshRenderer` holds `materials: Vec<MaterialHandle>` by `MeshData` group slot. Material shaders are `.wgsl` files defining `fn surface(in: SurfaceInput, p: <@material struct>) -> Surface`; see `crates/box_engine/examples/assets/stripes.wgsl`.
- Failures the user should see are logged with `tracing::warn!` / `tracing::error!` under a `box_*` target: the editor turns those into toasts and counts them on the Console tab. Never drop an error silently.
- **Audio** (`box_audio`, default `audio` feature): attach `AudioSource` for loops, music and emitters (fades on despawn and scene switch); send `PlaySound::new(path).at(pos)` for one-shots; `AudioListener` overrides the active camera; volumes are the `AudioSettings` settings resource. Games never use kira types. Only windowed runs open a device (`box_audio::enable_device_output`, called by the runner and the windowed editor); tests and headless runs are silent, and tests use `AudioOutput::Capture { sample_rate }` and `Audio::levels()`. The edit world never plays; editor Pause pauses audio through `Audio::set_paused`. Open project assets with `box_engine::asset_server(dir)`, not `AssetServer::new`, so audio files are indexed.
- **Assets load through `AssetServer`** (a world resource): `load::<T>(&AssetRef)` returns a handle at once; values appear in `Assets<T>` after `update` (`update_assets` system or `AssetPlugin`). Importers run on worker threads and never touch the World. Sub-assets are `file#Label` (`Mesh/<name>`, `Material/<name>`, `Texture/<i>`, `Scene`). The server writes `.meta` files only to create missing ones, give copied files fresh ids, and in `rename`.
- **Asset references in scenes resolve at runtime through `box_engine::asset_glue`:** never build `MeshRenderer`s for `MeshAsset` or `PrefabInstance` by hand. Prefab contents carry `prefab::Instanced`: never save or edit them; use `prefab::editable_ancestor` to map to the root. A world gets assets by holding an `AssetServer` resource; a Play world gets `copy_loaded_assets` plus `AssetForwarder` instead and never holds its own server.
- **Runtime scenes:** `Scenes::switch`/`load_additive`/`unload` requests apply at the start of the next `Update`. Entities spawned at runtime survive a switch unless parented under a scene entity or tagged with `SceneInstance`.
- **Live control socket** (`box_engine::control`): opt-in only. It binds 127.0.0.1 on a free port and writes `<project>/.box/control.json` `{version, pid, port, token, kind, scene}` (0600 on Unix, removed on drop). Every request needs the token. Hosts call `ControlServer::poll(&mut host)` once per frame on the main thread; no thread touches the World. Edits go through `control::apply_to_world` (`box_core::edit`). `box mcp` writes the protocol to stdout: code it reaches must never print to stdout; log with `tracing` (stderr).
- Build the simplest thing the current milestone needs. Later-milestone features belong in the docs, not in the code.

## Gotchas

- Editor toasts come only from the `box` and `box_*` log targets (`feedback.rs`); a game crate's `warn!`/`error!` (its own module target) reaches the Console but not a toast. Use `warn!(target: "box_game", ...)` for a game message that should toast.
- An app started by `open`/Finder runs in `/` with its own macOS privacy permissions; files on other volumes make macOS ask the user, so tests launching through `open` use the system temp folder.
- Loading only migrates in memory; files are rewritten only by `box upgrade`, a player's `--upgrade`, or the editor's Upgrade prompt, after a backup in `.box/backups/`. A read-only editor project refuses writes (`ensure_writable`).
- Runtime-only script spawns (enemies, projectiles) use `world.spawn{ transient = true }`: never saved, removed on load. `on_load` runs once `on_start` has returned (waits included); keep endless loops in `task.spawn`. An empty `MeshAsset.materials` uses the imported mesh's own materials.
- `cargo test --workspace` unifies features, so box_engine there has every module; `minimal_native`'s absence test only checks under `cargo test -p minimal_native`. Workspace dependencies keep default features: a member that opts out writes a `path` dependency with `default-features = false` (edition 2024 rejects it on `workspace = true`).
- luau-lsp (1.70.1, release binary from github.com/JohnnyMorganz/luau-lsp; not in Homebrew) reads definitions only as `declare extern type X with … end` and `export type`; plain `type` aliases there are invisible to scripts and Luau keywords as field names must be quoted. The generator (`box_script::types`) handles this; regenerate committed `.box/types/box.d.luau` files after API changes (`box script types`). Every declaration in `ScriptApi::definitions()` needs a `--- description` line above it (luau-lsp shows it on hover; `box_script::docs` builds the reference from it) and every API a `doc()` overview; after API changes also regenerate `docs/reference`.
- `box_engine`'s `dynamics` feature enables `box_script/dynamics` (collision callbacks, forces); `script` enables `box_ui/script`.
- `Events<T>` keep an event for two frames, so read UI and save events every frame. In the editor, Escape returns input to the editor, so `ui_back` reaches a game in Play only from Backspace or gamepad East. The overlay draws into a plain view of the target; UI colours are sRGB as written; image nodes expect sRGB images. System labels: `ui_input` at the start of Update; `ui_strings` then `ui_layout` in PostUpdate, after `ui_screen`; a menu opened by a game system in Update captures input from the next frame.
- Luau whole numbers come back as `mlua::Value::Integer`; match both number variants. Errors raised in Rust reach a script's `pcall` as userdata (`tostring(err)`). A `.luau` file's top level runs once at import (to read `properties`): engine globals are stand-ins there; touch the world in callbacks.
- rapier starts only when a `RigidBody` exists (`world.contains_resource::<Dynamics>()`). Colliders on children of a body are not part of it (warned once). Bodies that start overlapping push apart violently: put projectiles that share a spawn point on a layer that ignores itself. `KinematicCharacter::mass` and `Collider` friction/restitution do nothing without `dynamics`. New engine settings resources change the settings lists in the cli, editor and settings tests.
- Material shaders cannot bind textures (rebuild noise procedurally in the shader). WGSL reserves `smooth` and `patch`. In a material shader, a `let` of a constant vector used to build another can trip naga's pipeline-constant pass (`ExpressionAlreadyInScope`) at pipeline creation; making the vector non-constant fixes it.
- box_arch meshes have no tangents, so normal maps do nothing on them.
- Check boxes in the editor use `widgets::checkbox_labeled` (or `widgets::checkbox` in a field row), never `egui::Ui::checkbox`: egui draws its box in the field colour without a border, invisible on menus and windows. `crates/box_editor/clippy.toml` disallows it.
- Inspector rows go through `panes::inspector::rows_ui` (nested structs fold, closed by default; `fold_open` / `set_fold_open` by field path). A test that reads a nested field must open its heading first (click its label).
- The prepass depth is bound as `opaque_depth` (frame binding 7) only on frames where the prepass ran (`globals.scene_depth_on`). Long inspector panels can push rows below the window: editor tests scroll before clicking.
- `box_arch::ArchPlugin`'s anchors also run in the editor's edit world; systems added that way must be change-driven and read only saved data.
- wgpu 30 changed many descriptor types (optional bind group layouts and vertex buffers, `CurrentSurfaceTexture` enum, surface `color_space`). Read the source in `~/.cargo/registry/src/*/wgpu-30.0.2` rather than relying on older examples.
- Shaders hot-reload from `crates/box_render/shaders` in debug builds. A broken shader logs an error and keeps the last good pipeline.
- Golden references were recorded on Apple Silicon (Metal). Small differences on other GPUs are expected. `golden::DEFAULT_TOLERANCE` allows 0.05% bad pixels and no 8-connected bad region over 24 px, so a missing small object fails.
- Asset IDs are unique per process, not per store. Never assume a fresh `Assets` starts at 1.
- Editor document flows (unsaved-changes and recovery prompts, Save As, New/Open Project) are plain methods on `Editor` in `crates/box_editor/src/dialogs.rs` (`begin`, `answer_*`, `request_quit`); test them headlessly through those. Native dialogs run only after `Editor::with_native_dialogs()`.
- `app_with_world` replaces the `App::new` world, so it must insert every resource `App::new` does. A missing `FixedTime` silently disabled FixedUpdate until M3.
- During Play, `EditorState::world` is the *play* world; the edit world is parked until Stop. Anything that saves or applies edit commands must check `state.is_playing()` or stop Play first, as the document actions do.
- Panics inside guarded game code (Play mode) are recorded by a process-wide panic hook and not printed; the editor logs them once. Panics anywhere else print as usual.
- Live control is polled on the editor's main thread (`Editor::poll_control`, called by the windowed loop and `Headless::frame`). Tests drive a headless editor from the main thread and run the `ControlClient` or `box mcp` on another thread (see `crates/box_editor/tests/control.rs`, `apps/cli/tests/mcp.rs::mcp_drives_the_running_editor`, the M3 acceptance test). Editor-specific error codes: `play_failed`, `game_panic`.
- Multi-entity edits go through `EditorState::set_field_on` / `set_fields` (one bookkeeping pass per batch); calling `set_field` per entity in a loop runs the per-edit bookkeeping N times (measured 20–50 ms per frame at 1,000 entities).
- `tracing` interest is cached globally (`box_proc/tests/derive_warnings.rs` was split out for this): a test that captures logs with a scoped subscriber must be the only test in its binary.
- Read `@builtin(instance_index)` (`in.instance`) only in the `@vertex` function itself and pass it to helpers as a `u32`: on DX12 naga adds the draw's first instance only there, so a helper reading `in.instance` loads the wrong object (shadows and skinned meshes broke this way; docs/WINDOWS_ISSUES.md).
- Engine shaders use pipeline-overridable constants (`ALPHA_MODE`, `DOUBLE_SIDED`, `ALPHA_CUTOFF`) instead of separate modules. WGSL entry points cannot call each other; factor shared code into helper functions. The selection outline mask is `R32Uint`.
- The editor's `AssetServer` is a resource of the edit world and is recreated whenever the world is replaced; during Play it drives the parked edit world (`EditorState::edit_world`). Opening a project in the editor creates missing `.meta` files; commit them.
- Tools that call only `sync_scene_meshes` get instanced prefab contents one frame late (they spawn after that frame's propagation); call `sync_assets` before `propagate_transforms` when the first frame matters. Headless captures must call `settle_assets` (the runner and `box render` already do).
- Menu items and the command palette share one action registry (`crates/box_editor/src/actions.rs`): add an `Action` there (and a `menu_item(ui, state, "id")` line in `toolbar.rs` for a menu). Game code and editor tools add palette actions with `EditorState::register_action(Action::new(id, category, label, run).enabled_when(..))`; this is the M5 tool extension point.
- Keyboard shortcuts live in one table, `crates/box_editor/src/shortcuts.rs`; add new ones there (the Help modal and tooltips read it). Editor preferences (snap steps, navigation hint) are in `<project>/.box/editor.json`.
- `World::get`/`get_mut` borrow at run time and panic inside hecs ("already borrowed") when the same component is borrowed elsewhere (a live guard, a `query` loop); prefer `component_mut`/`query_mut` with `&mut World`.
- Never insert `Parent` yourself; use `world.set_parent` (a bare `Parent` warns once). Never write `GlobalTransform`.
- `Physics` queries see colliders as of the last `PostUpdate`; one spawned in `Update` is found from the next frame.
- A native project's editor bin needs `--features editor` (`cargo editor`).
- Terminal logs default to `warn,box=info` on stderr (no ANSI when piped); `RUST_LOG` overrides. CLI JSON results carry a `problems` list; while a command collects it, `box*` warnings are not repeated on stderr.
- `EditorState::undo`/`redo` step the inspected material file's history while one is shown; use `undo_scene`/`redo_scene` for the scene's. `box_render::Hidden` is an editor-only runtime marker; never add it to Play worlds.
- `register_settings` engine types (`AudioSettings`) make the editor write `assets/settings/AudioSettings.json` into every project it opens; commit it.
- In a native project, `box` and `box mcp` know game components only through `.box/registry.json`; if `check` reports `registry_stale` or `registry_missing`, run the hint's command.
- On Windows, Visual Studio Build Tools need the C++ ATL component (`Microsoft.VisualStudio.Component.VC.ATL`) besides the C++ workload: wgpu's DX12 shader compiler (`mach-dxcompiler-rs`) links `atls.lib`, and every binary fails with `LNK1104` without it.
- On macOS a window that is fully hidden (other windows on top, screen locked) is reported occluded; the runner pauses rendering until it is visible again. For automated runs use `--capture`.

## CI

The GitHub Actions workflow is `.github/workflows/ci.yml`: fmt, clippy, tests and examples on macOS and Windows (GPU tests skipped via `BOX_SKIP_GPU_TESTS=1`), plus a `features` matrix job (box_engine per module set) and a `lean` job (minimal_native, module libraries without optional features), both on Linux. Docs-only changes do not trigger it; a new push to a pull request cancels the older run; the Rust cache is saved even when a job fails. On a private repository, minutes count against the plan (macOS ×10, Windows ×2): keep macOS jobs few. Pushing changes to the workflow requires a GitHub token with the `workflow` scope.

## Published copies

This repository is published from a source repository that holds some private paths (an exclusion list there names them). Private paths are never copied into a published copy, and the publishing step fails on any mention of them.

- Never reference a private path, or what it contains, from a file that is published (docs, code, comments, tests, `Cargo.toml`). Keep shared wording generic.
- Tests, examples and workspace members must not depend on private paths; a test that needs private data lives in a private file (integration tests are discovered by file, so a missing file simply drops out).
- A private directory may carry its own `AGENTS.md`; read it when working there.

## Working with other agents

Assume another agent may be editing the repository. Run `git status` before building or committing, commit only files you changed, and never revert work you did not do.
