# Risks

Technical and project risks, the experiments that validate them, and mitigations. Likelihood and impact are judgments, not measurements.

Identifier note: **R** numbers here are risks. Renderer stages are written **RS1–RS5** to avoid confusion.

## 1. Risk register

| # | Risk | Likelihood | Impact | Validation | Mitigation |
|---|---|---|---|---|---|
| R1 | **Scope exceeds a small team.** An engine, an editor, a procedural toolkit and two games are each large. | High | High | Every milestone has explicit exclusions and acceptance criteria. | Strict milestone scope; features enter only when a milestone needs them; proven libraries for infrastructure; the deferred lists in each document are binding. |
| R2 | **The editor does not reach a professional look and feel on egui.** | Medium | High | Spike S1 | Custom theme and widgets. Editor logic kept free of UI types. Fallback: gpui. |
| R3 | **Reflection is a poor fit or too costly** (compile time, upgrade churn, API leakage). | Medium | High | Spike S2 | All use goes through `box_core::reflect`. Fallback: a minimal own derive. |
| R4 | **Engine overfits the reference game.** | Medium | High | M3 sample game; M7 and M8 | The architecture module is an optional plugin outside the engine crates. A different sample game exists from M3. M8 is a release gate. Renderer items driven by the construction slice are labelled as such. |
| R5 | **Procedural junctions look bad** (walls meeting walls, roofs, terrain). | Medium (was high; lowered after S6) | High for construction games | S6 done for walls, corners, openings, simple roofs, lathe junctions. Roof runs with valleys and side-on abutment remain: early M6 task | Joint lines and a shared (U, v, w) wall mapping; explicit junction kinds; ownership decided by game rules; per-junction golden captures. |
| R6 | **Frame spikes from mesh regeneration and upload.** | Medium | Medium | Spike S3 in M1; latency benchmark in M5 | Throttled flush; time budget per flush; background jobs and an upload budget when measurement calls for them. |
| R7 | **Dependency churn.** wgpu ships a breaking major roughly quarterly; egui, bevy_reflect, rapier and mlua also move quickly. | High | Medium | Track upgrade cost at each upgrade | Pin versions; use each dependency through one crate; upgrade wgpu only when egui-wgpu supports it; golden tests before and after. |
| R8 | **Shader module system.** WESL is pre-1.0 and may break or report errors poorly. | Medium | Low | Evaluation at M4 | M1 uses plain WGSL with our own include step. WESL is adopted at M4 only if stable. |
| R9 | **Pipeline compile hitches.** wgpu has no pipeline cache on Metal or DX12. | Medium | Medium | Measure in M1 and M4 | Create pipelines at load time; keep permutation count low; warm up on scene load. |
| R10 | **MSAA with prepass-driven effects** (SSAO, water depth fade) produces edge artefacts or costs too much. | Low (was medium) | Medium | S5 done (RS3) | **Retired in RS3:** single-sample depth + normal prepass, half-resolution SSAO, and a per-fragment depth-aware upsample in the forward shader, so every MSAA fragment uses its own surface's occlusion. An MSAA prepass with a manual resolve (sample 0/nearest/farthest) gave the same edges at 3–4x the cost; a non-depth-aware upsample left about 800 halo pixels at 2560x1440. Water depth fade will need a resolved main depth later. |
| R11 | **Script binding layer is costly to maintain** and the API freezes too early. | Medium | Medium | Spike S4 done; M7 built; M8 | Generate bindings from the registry; keep the API small and unstable until M9. **M7:** components, resources and events bind through the registry with no per-type code; hand-written bindings are small per-crate `ScriptApi`s; type definitions are generated, so a binding is one place. |
| R12 | **A game crash in Play mode takes down the editor.** | Medium | Medium | Play round-trip and fault-injection tests in M3 | Autosave before Play; catch script errors and, where possible, panics; out-of-process play remains reachable. |
| R13 | **Porting the reference game is larger than expected.** It is a large existing codebase with many custom shaders. | High | Medium | M6 is a slice, not a port | M6 targets one small structure. A full port is a separate project after the engine is proven. |
| R14 | **Windows diverges** because development happens on macOS. | Medium | Medium | CI build and tests from M1; manual smoke run per milestone; parity pass in M9 | DX12 with static DXC; platform code confined to a few crates. |
| R15 | **Golden-image tests are flaky** on virtualized CI GPUs or differ by backend. | Medium | Low | First golden test in M1 | Goldens run locally on the Mac until M9; per-platform references then. |
| R16 | **Export pipeline complexity**: patching a prebuilt player into a signed `.app` or `.exe` without a toolchain. | Medium | Medium | S7 done (M9) | Start with unsigned and ad-hoc signed builds; document notarization as a user step. **Outcome:** ad-hoc `.app` signing and PE resource patching (`editpe`) work without a toolchain. Open: running exported games on real Windows, Windows templates built on CI, notarization left to the user. See [EXPORT.md](EXPORT.md). |
| R17 | **No permissive straight-skeleton library** for roofs over arbitrary footprints. | High | Low | — | Closed-form roofs first; port or write a straight-skeleton algorithm later. |
| R18 | **In-game UI is underdesigned.** egui is a stopgap, and a script-facing UI API does not exist yet. | High | Medium | Decision D11 before M7 | Native games use egui directly through M6. The script-facing API is designed in M7 against the second game's needs. |
| R19 | **Compile times slow iteration** as the workspace grows. | Medium | Medium | Measure at M1 and each milestone | Dev profile tuning; few crates; scripts and reflected data for tuning. |
| R20 | **Text input and IME issues** on macOS through winit. | Low | Low | Test before M9 | Accept until external release. |
| R21 | **Asset edge cases**: FSEvents noise, atomic saves, duplicate IDs. | Medium | Low | Hot-reload tests in M4 | Watch directories; debounce; ignore metadata events; ID conflict rule. |
| R22 | **BC texture support on Apple Silicon behaves differently than expected** through wgpu. | Low | Low | Hardware check in M9, when compression is added | Codec trait allows ASTC or uncompressed. |
| R23 | **M7 is large.** Scripting, dynamics, skinned animation, particles, local lights, UI and save games in one milestone. | High | Medium | Each feature has its own test scene and can be verified alone | Build each to the minimum the chosen second game needs; the choice of game (Q5) may remove items; split M7 if it stalls. |
| R24 | **Entity model limits scale.** Systems are `fn(&mut World)` with no declared access, so they cannot be parallelized later without breaking plugins; scripts add per-call overhead. | Medium | Medium | M3 benchmark of 5,000 moving entities; M7 script benchmarks done | Runtime entities are cheap (no mandatory `Uid` or `Name`); batch script queries; hot loops in native code. Accept a ceiling in the thousands of active entities. **Measured (M7):** 10,000 script callbacks per frame 0.6 ms; batch query over 5,000 entities with a typed write each 0.53 ms; generic component copies about 0.6 µs per row, so hot loops use typed accessors. |
| R25 | **Shadow casters were not culled** (every caster in all four cascades). | Low (was high) | Medium | Showcase draw counts; M5 procedural reference scene | **Mitigated in M2:** casters are culled per cascade against the cascade's light-space box, which reaches the shadow distance toward the light, so off-screen casters that shadow visible ground still cast; casters outside every cascade and the view take no uniform slot. Showcase 162 → 102 draws (shadow draws 128 → 68), triangles 29,550 → 17,758, images byte-identical. Remaining: per-cascade lists are a linear scan; procedural worlds need a spatial structure (M5). |
| R26 | **The editor's window and surface path has never run on DX12/Windows.** M1's Windows run and CI are still open and the editor builds on the same surface code (non-sRGB surface with an sRGB view). | Medium | Medium | Windows smoke run (owner, or CI once the `workflow` token scope exists) | Run `box-editor --capture` and the showcase on a Windows PC before M2 is accepted; fall back to an sRGB surface where the format pair is missing (already coded). |
